# Модель угроз MikroTik Route Sync

## Обзор

Документ описывает потенциальные угрозы безопасности для системы MikroTik Route Sync и применяемые контрмеры.

## Активы

1. **Конфигурация** — содержит пароли, токены, ключи API
2. **Маршруты MikroTik** — критичная сетевая инфраструктура
3. **Данные кэша** — ASN, WHOIS, RDAP результаты
4. **Логи** — могут содержать чувствительную информацию
5. **Telegram-бот** — канал управления и уведомлений

## Угрозы

### 1. Несанкционированный доступ к конфигурации

**Угроза:** Злоумышленник получает доступ к `config.yaml` и извлекает пароли/токены.

**Вероятность:** Средняя

**Влияние:** Высокое

**Контрмеры:**
- Права файла `0600`, директории `0700`
- Проверка прав при старте
- Отказ запуска при нарушении
- Маскирование секретов в CLI/Web
- Аудит изменений конфигурации

### 2. Подмена конфигурации

**Угроза:** Злоумышленник изменяет конфигурацию для перенаправления трафика.

**Вероятность:** Низкая

**Влияние:** Критическое

**Контрмеры:**
- Атомарная запись через tmpfile + rename
- Валидация конфигурации перед применением
- Hot-reload с rollback при ошибке
- Аудит всех изменений

### 3. SSRF через внешние API

**Угроза:** Злоумышленник заставляет систему обращаться к внутренним ресурсам.

**Вероятность:** Средняя

**Влияние:** Высокое

**Контрмеры:**
- Whitelist разрешённых URL
- Блокировка private/loopback адресов
- Проверка схемы URL (только http/https)
- Ограничение редиректов (≤3)

### 4. Отказ в обслуживании (DoS)

**Угроза:** Злоумышленник перегружает систему через частые запросы.

**Вероятность:** Средняя

**Влияние:** Среднее

**Контрмеры:**
- Rate limiting на Web API (100/мин)
- Rate limiting на Telegram (1/сек)
- Rate limiting на MikroTik API (20/сек)
- Circuit Breaker для внешних API
- Ограничение размера запросов (≤1 МБ)

### 5. Массовое удаление маршрутов

**Угроза:** Ошибка в collector/validator приводит к удалению всех маршрутов.

**Вероятность:** Средняя

**Влияние:** Критическое

**Контрмеры:**
- Safe-diff проверка (max_delete_ratio = 50%)
- Fail-closed (не удалять при ошибке)
- Rollback при сбое
- Snapshot перед применением
- Требование `--force` для массовых изменений

### 6. Компрометация Telegram-бота

**Угроза:** Злоумышленник получает управление через Telegram.

**Вероятность:** Низкая

**Влияние:** Высокое

**Контрмеры:**
- Авторизация только по `authorized_chat_ids`
- Не отвечать неавторизованным
- Rate limit на команды
- Логирование попыток доступа

### 7. Утечка секретов через логи

**Угроза:** Пароли/токены попадают в логи.

**Вероятность:** Средняя

**Влияние:** Высокое

**Контрмеры:**
- Redaction в логах (password, token, secret, api_key)
- Запрет логирования HTTP-заголовков Authorization
- Маскирование в ошибках
- Ограничение verbose-логирования

### 8. Man-in-the-Middle (MITM)

**Угроза:** Перехват трафика между приложением и MikroTik/внешними API.

**Вероятность:** Низкая (в домашней сети)

**Влияние:** Высокое

**Контрмеры:**
- TLS 1.2+ по умолчанию
- Verify SSL включён по умолчанию
- Modern cipher suites
- HSTS при HTTPS
- Certificate pinning (опционально)
