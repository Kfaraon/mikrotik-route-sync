# Политика безопасности MikroTik Route Sync

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 1.x    | ✅ Активная |
| < 1.0  | ❌ Не поддерживается |

Обновления безопасности выпускаются для последней стабильной версии.

## Сообщение об уязвимости

Если вы обнаружили уязвимость безопасности, **не создавайте публичный issue**.

Отправьте отчёт на email: **security@kfaraon.dev** (или через GitHub Security Advisory).

Включите в отчёт:

- Описание уязвимости
- Шаги для воспроизведения
- Версию приложения (`./app version`)
- Ожидаемый и фактический результат
- Потенциальное влияние

## Сроки ответа

- **Подтверждение получения**: в течение 48 часов
- **Первичная оценка**: в течение 7 дней
- **План исправления**: в течение 14 дней
- **Патч**: в течение 30 дней (зависит от сложности)

## Раскрытие информации

Мы следуем принципу **координативного раскрытия** (Coordinated Disclosure):

1. Получаем отчёт
2. Подтверждаем и оцениваем
3. Разрабатываем и тестируем патч
4. Выпускаем обновление
5. Публично раскрываем информацию после установки патча у пользователей

Критические уязвимости раскрываются **после** выпуска патча, с указанием автора отчёта (если он согласен).

## Безопасная конфигурация

### Критические настройки

- Права файла `config.yaml` — строго `0600`
- Права директории конфига — строго `0700`
- Приложение откажется запускаться при нарушении прав
- Никогда не коммитьте `config.yaml` в git (уже в `.gitignore`)

### Секреты

- Пароли и токены хранятся в `config.yaml` в открытом виде — **защитите файл**
- Рекомендуется использовать ENV-переменные или Docker secrets:
  - `MRS_MIKROTIK_PASSWORD`
  - `MRS_TELEGRAM_BOT_TOKEN`
  - `MRS_WEB_PASSWORD`
  - `MRS_BGPVIEW_API_KEY`
- Поддерживаются `_FILE`-варианты для Docker secrets

### Сеть

- Web UI по умолчанию слушает `127.0.0.1:8080` — **не открывайте в интернет**
- Используйте `allowed_cidrs` для ограничения доступа (LAN/VPN)
- За reverse proxy (nginx/traefik) настройте `trusted_proxies`
- Включите `verify_ssl: true` для MikroTik в production

### MikroTik

- Создайте **отдельного пользователя API** с минимальными правами:
  - `read`, `write`, `rest-api`, `api`, `policy`
- Ограничьте доступ по IP через `/ip service` или firewall
- Не используйте `admin` для API

### Telegram-бот

- Указывайте **только свои** `chat_id` в `authorized_chat_ids`
- Бот игнорирует неавторизованных пользователей (не отвечает, чтобы не раскрывать существование)
- Не передавайте боту чувствительные данные в сообщениях

## Архитектурные гарантии безопасности

### Fail-closed

При любой ошибке (collector, validator, API) существующие маршруты **не удаляются**. Синхронизация прерывается, отправляется уведомление.

### Safe-diff

Массовое удаление маршрутов блокируется, если `deleted / existing > 0.5`. Требуется явное подтверждение через `--force`.

### Изоляция сервисов

Каждый сервис обрабатывается независимо. Ошибка в `instagram` не затрагивает маршруты `youtube` или `cloudflare`. Все операции фильтруются по комментарию `AUTO:<service>`.

### Rollback

Перед применением изменений создаётся снимок. При сбое выполняется автоматический откат. Частичный rollback помечает сервис как `degraded`.

### Защита от SSRF

Внешние HTTP-запросы блокируются к private/loopback/link-local адресам. Разрешены только `http://` и `https://` схемы.

### Redaction секретов

Пароли, токены, API-ключи автоматически маскируются в:
- Логах (JSON-формат)
- Ошибках, отправляемых в Telegram
- Ответах REST API
- CLI-выводе

### Защита входных данных

- Имя сервиса: `^[a-z0-9][a-z0-9_-]{0,63}$`
- ASN: `^AS\d{1,10}$`
- URL: только `http/https`
- Cron: только через валидированный парсер
- Комментарии RouterOS: экранирование `"`, `\`, `\n`

## Аудит и наблюдаемость

- Все изменения конфигурации логируются (без значений секретов)
- Попытки неавторизованного доступа логируются с `WARN`
- История синхронизаций сохраняется в bbolt
- Структурированные логи (JSON) с ротацией и сжатием

## Supply chain security

- `go.sum` зафиксирован в репозитории
- Зависимости — только популярные, с активной поддержкой
- Перед релизом выполняются:
  - `govulncheck ./...`
  - `gosec ./...`
  - `golangci-lint run`
- Статический бинарник (`CGO_ENABLED=0`)
- Multi-stage Docker build (runtime — `scratch`)
